# 가림 위치 이력 가설 1차 검증 보고서

- 작성일: 2026-11-26
- 대상: OA-SORT 재현본(baseline 노트북의 `oa_sort_impl.py`)을 기준선으로 한 가설 검증
- 코드: 이 저장소의 `occflow/` (사용법은 `occflow/README.md`)

## 요약

1. **실패 위치:** 재현 OA-SORT의 ID 오류 중 93~94%는 3명 이상이 겹친 상황에서 생긴다.
   FN의 78%는 같은 위치에 고신뢰 검출이 있었다. 즉 검출이 아니라 연결과 출력 단계에서 빠진 것이다.
2. **가설 검증:** 교집합 위치 \((u_t, v_t)\) 이력은 GT 박스만 쓴 오라클(val 전체 25개)에서도 단순 직선 운동 예측보다 모든 조건에서 낮았다.
   추적기에 비용 항으로 넣었을 때는 IDSW가 156 → 148로 줄었지만 HOTA는 66.65 → 65.95, AssA는 55.36 → 54.34로 떨어졌다(0026 + 0079).
3. **판단 보류:** 교차 후 양방향으로 다시 잇는 방식은 GT에서는 앞 구간만 보는 것보다 나았다(0.809 vs 0.748).
   그러나 실제 결과에서는 고친 경우가 0건이었다. 오류가 나는 뭉침은 정해진 시간 안에 흩어지지 않아 판단 대상에 들어오지 못했다.
4. **해석:** 교집합 위치는 두 박스 좌표에서 결정되는 값이라, 그 시간 변화는 상대 운동과 거의 같은 정보다.
   위치·운동만으로 구분하기 어려운 구간을 풀려면 박스 밖의 단서(외형 등)나 더 긴 기억이 필요하다.

## 3. 가설 검증: 가림 위치 이력 비용 (`occflow/hook.py`, `occflow/integration/oa_flow.py`)

### 3-1. 구현
- 교집합 중심의 대상 박스 내 상대 좌표 \((u_t, v_t)\)와 상대 중심 오프셋 \((dx, dy)\)를 가림 상대별 이력으로 저장했다.
  오프셋은 갈라진 직후 겹침이 0일 때도 흐름을 잇기 위해 추가했다.
- 1차 매칭 비용(HMIoU + 방향 + 점수 + OAO)에 \(\lambda_h \cdot\) (후보별 흐름 불일치 − 행 최소값)을 더했다.
  경합 후보가 2개 이상이고 흐름 신뢰도가 충분할 때만 적용했다.
- 함께 시험한 모듈: 가림 중 놓친 트랙 재연결, 교차 쌍 ID 사후 점검. 둘 다 실제 영상에서 적용 0건.

### 3-2. 추적 결과 (0026 + 0079 합산)

| 모드 | HOTA | AssA | IDF1 | IDSW | FN |
|---|---:|---:|---:|---:|---:|
| hybrid | 68.49 | 58.55 | 74.51 | 158 | 1079 |
| oa_sort (재현) | 66.65 | 55.36 | 71.93 | 156 | 1085 |
| oa_sort + 흐름 비용 | 65.95 | 54.34 | 71.31 | 148 | 1090 |

흐름 항이 결정을 바꾼 48건을 GT로 판정했다(`tools/diagnose_flow.py`). 고침 19건, 망침 18건, 불명 11건이었다.
흐름 신뢰도와 일관성 점수로는 고침과 망침이 구분되지 않았다.

### 3-3. 오라클: GT 박스만으로 가설 검증 (`tools/oracle_flow.py`, val 전체)

겹친 GT 쌍마다 정답 배정과 교환 배정 중 하나를 고르게 하고, 두 방식을 비교했다.
흐름은 가림 이력 불일치를 쓰고, 운동은 각자 궤적을 직선으로 연장한다. 관측 공백은 가림을 흉내 낸 것이다.

| 잡음 | 관측 공백 | 판정 수 | 흐름 | 운동 | 판단이 갈린 경우 흐름 승 / 운동 승 |
|---|---:|---:|---:|---:|---|
| 0 | 1 | 52,148 | 0.994 | 0.996 | 71 / 181 |
| 0 | 5 | 46,960 | 0.952 | 0.966 | 533 / 1,200 |
| 0 | 10 | 42,721 | 0.896 | 0.921 | 1,213 / 2,260 |
| 0 | 15 | 39,540 | 0.848 | 0.879 | 1,779 / 3,001 |
| 3% | 15 | 39,204 | 0.830 | 0.851 | 2,149 / 2,975 |

- 모든 조건에서 운동이 앞섰다. 흐름이 나은 시퀀스는 조건마다 1~3개였고 매번 달랐다.
- 운동이 틀린 프레임에서 흐름이 맞힌 비율은 약 36~37%다. 보조 신호로도 약하다.
- 해석: \((u_t, v_t)\)와 오프셋은 두 박스에서 계산되는 값이다. 그 추세를 외삽하면 두 궤적을 각각 외삽한 것과 거의 같은 정보가 된다.
  계획서 6장의 B/C 비교만으로는 "시간적 이력이 운동 정보와 다른 정보를 주는가"에 답할 수 없다. 운동만 쓴 대조군과의 비교가 필요하다.

## 4. 판단 보류 실험 (`occflow/deferred.py`, `tools/defer_resolve.py`)

교차 중에는 ID를 확정하지 않고, 흩어진 뒤 교차 전후 구간을 양방향 외삽으로 이어 원래대로 둘지 바꿀지(여러 명이면 순열) 정했다.
고정 지연 후처리이고, 결정 지연은 중앙값 15~21프레임이다.

| 단계 | 두 사람 단위 | 여러 명 묶음 단위 |
|---|---|---|
| GT 오라클 정확도 (양방향 / 앞 구간만) | 0.809 / 0.748 | 0.793 / 0.727 (3명 이상 0.50 / 0.44) |
| 실제 적용, GT 판정 (oa_sort) | 고침 0, 잘못 바꿈 4 | 고침 0, 잘못 바꿈 3 |
| oa_sort HOTA (원래 66.65) | 65.45 | 65.57 |

- 판단할 수 있었던 구간(멤버가 깨끗하게 흩어짐)에서는 교환이 필요한 경우가 0건이었다. 추적기가 이미 맞게 처리했다.
- 오류가 나는 뭉침은 지연 안에 깨끗하게 흩어지지 않아 판단 대상에서 빠졌다(묶음 구간의 약 60%).

## 5. OA-SORT 한계와 우리 가설의 범위

| 관찰 | 근거 | 가설로 해결 가능한가 |
|---|---|---|
| ID 오류가 3명 이상 뭉침에 집중 | 2절 (93~94%) | 박스 위치·운동 기반으로는 어렵다 (3, 4절) |
| 틀린 ID가 오래 유지됨 (IDSW 대비 AssA 하락이 큼) | 0079 틀린 ID 프레임 +537 | 사후 점검을 운동 정보로 하면 판정 가능한 구간이 거의 없다 |
| FN 대부분이 검출은 있는데 출력 누락 | FN의 78% | 가설과 별개. 재생성 시 min_hits 대기, 연결 실패 등 분석 필요 |
| 하단 y 기반 앞뒤 추정이 하체 가림·점프에서 불확실 (논문 §5.4) | 0026 | 앞뒤 신뢰도로 가중치를 낮췄지만 효과 확인 못 함 |

## 6. 다음 방향 (교수님 피드백 반영, 논의 필요)

교수님 피드백 요지:
- 이력을 가진다면 관련 최신 논문을 정리할 것
- 장기간 ID를 유지할 때 기존 방법은 어떻게 처리하는지 조사할 것 (long-term memory)
- 장기 기억을 sliding window로 계속 따라가는 방식, 수학적 모델로 결과가 나오는지
- memory limit을 두고, 오류가 생기면 condition/confusion mode로 전환
- 분리될 때 각각의 attribute를 저장하는 방식
- 여러 명이 겹칠 때 attribute를 어떻게 저장할지, 3명이 되어도 찾아낼 수 있는지

이번 결과와 연결하면:
1. **뭉치기 직전 attribute 저장 → 흩어진 뒤 대조.** 운동 정보로는 판단이 안 되는 뭉침(2, 4절)에 직접 대응한다.
   후보 attribute는 외형 임베딩(ReID, Hybrid-SORT에 fast_reid 옵션 있음), 색 히스토그램, 박스 크기·비율 등이다.
   판단 보류 구조(`deferred.py`)는 그대로 쓰고, 연결 비용만 운동에서 attribute로 바꾸면 바로 시험할 수 있다.
2. **confusion mode.** 3명 이상 겹치는 동안은 "혼동 상태"로 표시하고, 관련 트랙들의 ID를 하나의 후보 집합으로 묶어 둔다.
   흩어지면 저장된 attribute로 순열을 다시 정한다. memory limit은 혼동 상태의 최대 지속 시간과 저장 attribute 수로 둔다.
3. **long-term memory 조사.** 외형 갤러리를 길게 유지하는 방식(DeepSORT 계열), 지수이동평균 외형(StrongSORT 등),
   메모리 뱅크 기반 Transformer 추적기, 오프라인 트랙렛 연결 방식을 비교한다. 목록과 세부 내용은 조사가 필요하다.
4. **검증 방식.** 이번처럼 GT 오라클로 먼저 판별력을 확인한다. attribute로 순열을 고르는 정확도가 운동보다 높은지,
   특히 3명 이상 뭉침에서 어떤지 본 뒤 추적기에 넣는다.

